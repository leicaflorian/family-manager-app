# Versions, changelog and releases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `./release` script on the owner's Mac that merges `dev` into `main`, has the `claude` CLI (Sonnet) write the changelog and the simple notes and suggest the bump, lets `php artisan app:release` confirm and write the files, dumps the production database when there are new migrations, then commits, tags and pushes; GitHub runs every check on the tag and only then publishes the release and deploys on Coolify.

**Architecture:** One version in `VERSION`, read by `config('app.version')` and by Vite (`__APP_BUILD__`). The PHP side (`App\Services\Release\*`, `App\Console\Commands\ReleaseCommand`) is pure and tested with Pest; the bash script does only git, `claude`, ssh and calls the command through Sail. `ci.yml` is a reusable workflow (push, PR, `workflow_call`); `release.yml` runs it on `v*` tags, then `gh release create` and the Coolify deploy API.

**Tech Stack:** Laravel 13, Laravel Prompts, Pest, bash, `claude` CLI (`-p --model sonnet --output-format json --json-schema`), GitHub Actions, Coolify API.

**Spec:** `docs/superpowers/specs/2026-11-15-releases-design.md`

## Global Constraints

- `VERSION` at the repo root holds `X.Y.Z` and a newline. Missing file: `config('app.version')` is `dev`, and the first release is `2.0.0` with no bump to choose.
- Bumps Claude may suggest: `minor`, `patch`. The owner may also pick `major`, or cancel.
- Changelog in English, in `CHANGELOG.md`, newest first, sections `## [X.Y.Z] - YYYY-MM-DD`.
- `resources/release/notes.json`: JSON array, newest first, entries `{ "version": "X.Y.Z", "date": "YYYY-MM-DD", "notes": { "it": [string, …], "en": [string, …] } }`. Its reader (`App\Services\ReleaseNotes`, `ReleaseNoteData`, the shared prop, the panel) belongs to another session: do not touch `app/Services/ReleaseNotes.php`, `app/Data/ReleaseNoteData.php`, `app/Http/Middleware/HandleInertiaRequests.php`, `app/Providers/AppServiceProvider.php`.
- Claude's answer: `{ "bump": "minor"|"patch", "reason": string, "changelog": string (markdown, English), "notes": { "it": [string, …≥1], "en": [string, …≥1] } }`, schema in `resources/release/response.schema.json`.
- Files the command hands to the script, in `storage/app/release/` (ignored by git, seen by the container): `response.json` (in), `version` and `tag-message.md` (out).
- Release commit message `Release vX.Y.Z`; annotated tag `vX.Y.Z` whose message is that version's changelog; merge message `Merge branch 'dev' for release`.
- Database dump before the push only when `git diff --name-only --diff-filter=A <last tag>..HEAD -- database/migrations` is not empty (with no tag: every migration counts): `ssh family-manager-prod`, container of MySQL uuid `xwdxjjleppacin2ses4d93xe`, `mysqldump --single-transaction --no-tablespaces family_manager_app` gzipped to `/root/backups/family-manager-app/before-vX.Y.Z-<YYYY-MM-DD-HHMM>.sql.gz`; the root password is read inside the container from `$MYSQL_ROOT_PASSWORD`, never written or printed; the dump counts only if it ends with `-- Dump completed`.
- Coolify: `https://coolify.leicaflorianrobert.dev`, deploy `GET /api/v1/deploy?uuid=$COOLIFY_APP_UUID` with `Authorization: Bearer $COOLIFY_TOKEN` (repository secrets). Auto-deploy on push is off in Coolify.
- Project rules of `AGENTS.md` (TDD, `declare(strict_types=1)`, PHPDoc everywhere, PHPStan 9, Rector, Pint, English code). Tests through Sail, Pest with its own database: `docker exec -u sail -e DB_DATABASE=testing_releases family-manager-app-laravel.test-1 php artisan test …` written out in full.
- Other sessions work in the repo: commit only your own files (`git add <paths>`, never `-A`).

## Review Focus

1. Claude fails (CLI exit ≠ 0, `is_error`, missing `structured_output`) → the script stops, `main` back to `origin/main`, back on `dev`, nothing pushed. Covered by the smoke test in Task 4.
2. The owner cancels at the prompt, or the answer is invalid → the command exits 1 and writes nothing; the script restores `main`. Tasks 3 and 4.
3. Merge conflict `dev` → `main` → `git merge --abort`, back on `dev`. Task 4.
4. The dump fails (ssh down, no `-- Dump completed`) → stop before the push, local tag deleted, `main` restored. Task 4 (stub ssh exiting 1).
5. A tag not on `main`, or `main` moved after the tag → no release / no deploy. Task 6.
6. Nothing to release (no commits since the last tag) → the script says so and stops before calling Claude. Task 4.

**Files:**

**Interfaces:**
- Produces:
  - `enum ReleaseBump: string { case Major = 'major'; case Minor = 'minor'; case Patch = 'patch'; }`
  - `final readonly class Version { static parse(string $value): self /* throws InvalidArgumentException */; bump(ReleaseBump $bump): self; __toString(): string; const FIRST = '2.0.0'; }`
  - `final readonly class ReleaseResponse { ReleaseBump $bump; string $reason; string $changelog; /** @var array{it: list<string>, en: list<string>} */ array $notes; static fromJson(string $json): self /* throws InvalidReleaseResponse */ }` — accepts only `minor`/`patch`, non-empty `reason` and `changelog`, ≥1 non-empty string per language, no other keys required.
  - `final class InvalidReleaseResponse extends RuntimeException` with a message that names the wrong field.
  - `final readonly class ReleaseFiles { __construct(string $root); current(): ?Version; write(Version $version, ReleaseResponse $response, CarbonImmutable $date): void; section(Version $version, ReleaseResponse $response, CarbonImmutable $date): string }` — `section()` is the `## [X.Y.Z] - YYYY-MM-DD` block (header, blank line, changelog, trailing newline) used both in `CHANGELOG.md` and as the tag message.

### Task 4: The `./release` script

**Files:**
- Create: `release` (bash, executable, at the root), `tests/release/smoke.sh` (bash, executable)

**Interfaces:**
- Consumes: Task 3's command and handoff files; `resources/release/prompt.md` and `response.schema.json`.
- Produces: `./release` (no arguments). For tests it reads overrides from the environment: `RELEASE_CLAUDE` (default `claude`), `RELEASE_ARTISAN` (default `./vendor/bin/sail artisan`), `RELEASE_SSH` (default `ssh family-manager-prod`), `RELEASE_REMOTE` (default `origin`).

- [ ] **Step 1: Write the smoke test** `tests/release/smoke.sh`: creates a temp dir with a bare remote and a clone (commits on `dev`, `main` behind, one file under `database/migrations/`), copies `release`, `resources/release/*` into it, puts stubs on `PATH`/env (a `claude` stub that prints the CLI JSON envelope `{"type":"result","is_error":false,"structured_output":{…}}` or fails on demand; an artisan stub that writes `VERSION`, the handoff files and exits 0 or 1 on demand; an ssh stub that prints `-- Dump completed` or exits 1 on demand) and asserts, one scenario each:
  1. happy path: remote `main` has `Release v2.0.0` on top of the merge, tag `v2.0.0` annotated on it, remote `dev` equals `main`, local branch is `dev`, the ssh stub was called (new migration);
  2. no new migration since the last tag → ssh stub not called;
  3. claude stub fails → exit ≠ 0, remote untouched, local `main` equals `origin/main`, on `dev`;
  4. artisan stub exits 1 (cancel) → same as 3, no local tag;
  5. ssh stub fails → same as 3, no local tag;
  6. dirty tree, or `dev` behind `origin/dev` → refuses before any merge;
  7. nothing since the last tag → "Nothing to release", claude stub not called;
  8. conflicting `main` → merge aborted, on `dev`.

- [ ] **Step 3: Implement `release`** (`set -euo pipefail`, a `trap` that on failure before the push runs `git merge --abort` if a merge is open, `git checkout main && git reset --hard <remote>/main`, `git tag -d vX` if created, `git checkout dev`; after the push it only prints what to rerun). Steps exactly as in the spec's flow (1–9). ### Task 6: Release on GitHub (`release.yml`)

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: Task 5's `ci.yml` via `workflow_call`.

- [ ] **Step 1: Write the workflow.** On `push: tags: ['v*']`. Job `guard` (checkout `fetch-depth: 0`): `git merge-base --is-ancestor "$GITHUB_SHA" origin/main` or fail with "The tag is not on main". Job `ci`: `uses: ./.github/workflows/ci.yml`, `secrets: inherit`, `needs: guard`. Job `release` (`needs: ci`, `permissions: contents: write`): message of the annotated tag (`git for-each-ref refs/tags/$GITHUB_REF_NAME --format='%(contents)'` after `git fetch --tags --force`) into a file, `gh release create "$GITHUB_REF_NAME" --title "$GITHUB_REF_NAME" --notes-file …`. Job `deploy` (`needs: release`): if `COOLIFY_TOKEN` or `COOLIFY_APP_UUID` is empty, write a notice "Coolify not set up yet, no deploy" and stop green; if `git ls-remote origin refs/heads/main` is not `$GITHUB_SHA`, fail with "main moved after the tag: deploy by hand"; otherwise `curl -fsS` the deploy API with the token in a header file (never echoed).
